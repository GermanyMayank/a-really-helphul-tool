About Unlock

Make your own copy

Your own private vault, in about 15 minutes.

This guide takes you from nothing to your own working copy of the app, click by click. You don't need to write code or install anything. Your copy is completely separate: nobody else can see your documents, and you can't see theirs.

  • FreeGitHub's free plan is enough
  • ~15 minmost of it is waiting
  • No codeonly clicking and pasting
  • Browser onlya laptop is easiest

What you are building

Three things, all on your own GitHub account. Once you see how they fit together, every step below makes sense.

1. The app (public)

Your copy ("fork") of this project's code. GitHub Pages turns it into a website at your own address. It holds code only, never documents, so it can be public. Free GitHub Pages needs it public.

2. The vault (private)

A separate private repository where your files are stored. Only you can open it. Every upload, rename and delete becomes a saved change there, so nothing is ever really lost.

3. The key (encrypted)

A GitHub access token that can open the vault and nothing else. It is locked with your password (AES-256) and stored in the app as config.js. Without your password it is useless.

Before you start

  • A GitHub account. Free. If you have none, do step 0.
  • A laptop or desktop browser (Chrome, Edge, Safari or Firefox). A phone works too, but GitHub's settings pages are fiddly on a small screen.
  • A password idea. At least 10 characters. A short sentence is easiest to type on a phone and hardest to guess, for example green bus to Dwarka at 7. Don't reuse a password from somewhere else.
  • 15 minutes and a phone to try it on at the end.
0

Create a GitHub account (skip if you have one)

3 minutes

  1. Open github.com/signup.
  2. Enter your email, a password and a username. Pick the username with care: it becomes part of your app's address (username.github.io).
  3. Solve the puzzle, then type the code GitHub emails you.
  4. If GitHub asks which plan you want, choose Free. Skip any survey.
  5. Recommended: turn on two-factor login under Settings › Password and authentication. Your account guards your documents, so it deserves a strong lock.

You should now: be signed in to GitHub and see your username in the top-right menu. Type it into the box above.

Part A

Copy the app

You make your own copy of the code and turn it into a website. At the end of Part A you have a working address, but it can't open anything yet.

1

Fork the project

1 minute

"Fork" is GitHub's word for "make my own copy of this repository".

  1. Make sure you are signed in to GitHub, then open the fork page: Fork the project
  2. Owner: your username.
  3. Repository name: keep a-really-helphul-tool (yes, "helphul" is how the original is spelled) or choose your own, for example my-documents. Only letters, numbers and dashes. If you change it, update "Name of your copy" at the top.
  4. Leave Copy the main branch only ticked.
  5. Click Create fork.

You should now see: a page titled YOUR-USERNAME/a-really-helphul-tool with a small line under it saying "forked from GermanyMayank/a-really-helphul-tool".

Is it a problem that the copy is public? No. It contains only code and, after step 8, your encrypted key. Your documents go into the private vault in step 5.

2

Allow the automatic checks to run

30 seconds

The project tests itself and publishes the website automatically ("GitHub Actions"). On a fresh fork GitHub switches this off until you say yes.

  1. Open the Actions tab of your copy: Open Actions
  2. Click the green button I understand my workflows, go ahead and enable them.

You should now see: "All workflows" on the left with Test and deploy listed under it. No runs yet is normal.

3

Turn on the website (GitHub Pages)

30 seconds

  1. Open Settings › Pages of your copy: Open Pages settings
  2. Under Build and deployment › Source, choose GitHub Actions.
  3. That's all. There is no Save button; the choice is stored at once.

Not "Deploy from a branch". That option would publish the code without testing it and skip the step that prepares the app. Always pick GitHub Actions.

4

Publish it for the first time

1 click, then 3 to 5 minutes of waiting

  1. Open the workflow: Open "Test and deploy"
  2. On the right, click Run workflow, keep Branch: main, and click the green Run workflow button.
  3. Reload the page after a few seconds. A run appears with a yellow dot. It runs about 280 browser checks first, then publishes. Wait until the dot turns into a green tick (3 to 5 minutes). You can do steps 5 and 6 meanwhile.
  4. Open your new address: Open my app

You should now see: the app's red lock screen asking for a password. Don't try to unlock yet: your copy still carries the original owner's key, which only opens their vault. Step 8 replaces it with yours.

Red cross instead of a green tick? See If something goes wrong. The most common cause is step 3 not being saved, and the fix takes 20 seconds.

Part B

Make the vault and the key

Now the place where your files will live, and a key that can open only that place.

5

Create the private vault

1 minute

  1. Open Create a new repository
  2. Owner: your username.
  3. Repository name: docsync-vault
  4. Visibility: Private. This is the one setting that really matters. Double-check it.
  5. Turn on Add a README file (sometimes shown as "Add README"). The app needs a repository that isn't completely empty.
  6. Leave .gitignore and license as they are, and click Create repository.

You should now see: a page titled YOUR-USERNAME/docsync-vault with a Private label next to the name and one file, README.md.

Never make the vault public. The setup page in step 7 refuses a public vault, but it's good to know why: anyone could read a public repository.

6

Create the access key (token)

2 minutes

A "fine-grained personal access token" is a key you can limit to one repository and one kind of access. The app uses it to read and save files in the vault.

  1. Open Create a fine-grained token
    (The long way: your picture › Settings › Developer settings › Personal access tokens › Fine-grained tokens › Generate new token.)
  2. Token name: helpful-tool-vault (any name; it's only a label for you).
  3. Resource owner: your username.
  4. Expiration: the longest you are comfortable with, for example one year. When it runs out the app stops unlocking, and you repeat steps 6 to 8 (5 minutes). GitHub emails you a week before.
  5. Repository access: choose Only select repositories, then pick docsync-vault. Only that one. Not your app copy, not "All repositories".
  6. Permissions: under Repository permissions (newer GitHub screens: click Add permissions first), find Contents and set it to Read and write. GitHub adds "Metadata: Read-only" by itself; that's correct. Leave everything else at No access.
  7. Click Generate token at the bottom, check the summary, and confirm.
  8. Click the copy icon next to the token. It starts with github_pat_.

Treat the token like a house key until step 7. GitHub shows it only once. Don't paste it into config.js, an email, a chat or a note you sync. If you lose it before step 7, just delete it on the tokens page and make a new one.

Part C

Connect the app to your vault

Lock the key with your password, put the locked key into your app, and you're done.

7

Lock the key with your password

1 minute (step 4 must have a green tick)

  1. Open the setup page of your copy: Open my setup page
    Address: https://YOUR-USERNAME.github.io/a-really-helphul-tool/setup.html
  2. GitHub username: already filled in. Check it.
  3. Private vault repo name: docsync-vault
  4. Fine-grained access token: paste the token from step 6.
  5. Choose a password and Repeat password. At least 10 characters, not a common word or pattern. This is the password you will type on every device.
  6. Click Test token and generate config. The page checks with GitHub that the key opens your vault and that the vault is private, then locks the key with your password. All of this happens inside your browser; your password is never sent anywhere.
  7. A box called Your new config.js appears. Click Copy.

You should now have: a block of text on your clipboard starting with // a really helpful tool: configuration and containing encryptedToken. It is safe to keep: it's useless without your password. Saving a copy in your notes now saves time later.

Write the password down somewhere safe. It can't be recovered or reset. If you forget it, your files are still fine in the vault: you just make a new token and do steps 6 to 8 again with a new password.

8

Put the locked key into your app

1 minute, then 3 to 5 minutes of waiting

  1. Open config.js in your copy, ready to edit: Edit my config.js
  2. Click into the text, select everything (Ctrl+A, on a Mac ⌘+A) and delete it. The old text is the original owner's locked key; it has to go completely.
  3. Paste your config (Ctrl+V or ⌘+V).
  4. Click Commit changes... (top right), keep Commit directly to the main branch, and click Commit changes.
  5. This starts "Test and deploy" by itself. Wait for the green tick: Watch it in Actions

You should now see: the file showing owner: "your-username" and repo: "docsync-vault", and a new green run in Actions.

config.js is the only file you ever need to edit. Everything else updates by itself when you get new versions.

9

Unlock and try it

2 minutes

  1. Open Open my app. If it was already open, reload it (Ctrl+Shift+R, on a Mac ⌘+Shift+R) so it picks up the new config.
  2. Type your password and press Unlock. The first unlock takes a second or two on purpose: that slowness is what makes guessing passwords impractical.
  3. Upload a test file: the upload button, drag and drop on a laptop, or paste a screenshot with Ctrl+V.
  4. Check it arrived in the vault: Open my vault's files
  5. Try the menu (⋯) on the file: preview, rename, delete, then restore it from the Trash.

You should now see: your file in the list, in a category picked from its name, and the same file under files/ in your private vault on GitHub. That's it: it works.

10

Put it on your phones

1 minute per device

Open https://YOUR-USERNAME.github.io/a-really-helphul-tool/ on the phone, unlock once, then:

  • iPhone / iPad (Safari): Share button › Add to Home Screen › Add.
  • Android (Chrome): menu ⋮ › Install app (or Add to Home screen).
  • Laptop (Chrome or Edge): the install icon at the right end of the address bar, or just bookmark it.

It then opens full screen like a normal app, even without a connection (you need the internet to load documents you haven't opened before). Every device needs the password once. The lock button wipes the key and every cached file from that device.

Getting new versions

When the original project gets a new version, your copy doesn't change by itself. Pulling it in takes two clicks:

  1. Open your copy on GitHub: Open my copy
  2. Above the file list, click Sync fork, then Update branch.
  3. Test and deploy starts by itself. When it's green, reload the app. If nothing starts after a minute, run it by hand as in step 4.

Your config.js is kept when you sync, because the update doesn't touch it. In the rare case GitHub says there is a conflict and only offers Discard commits: that's fine if you saved your config text in step 7. Discard, then do step 8 again with your saved text. Never paste the original owner's config.js into yours.

What changed in each version: the changelog, or What's new on the app's lock screen.

Everyday questions

How do I change my password?

Open your setup page (step 7) with the same token and a new password, then paste the result into config.js (step 8). If you no longer have the token, make a new one (step 6) first. Old devices will ask for the new password.

My token expired. What now?

The app will refuse to unlock. Make a new token (step 6), then steps 7 and 8. You can delete the old token on your tokens page. Your files are untouched.

I lost my phone. Can someone get in?

Only with your password, and only if the phone was still unlocked into the app. To cut it off completely: on your tokens page, delete the token. That stops every device at once. Then make a new token and do steps 7 and 8 to get back in on your other devices.

I deleted a file by mistake.

Tap Undo right away, or open Trash in the app: deleted files wait there for 30 days. After that, the file is still in the vault's history on GitHub: open the "Delete ..." change under Commits in your vault and download it from the version before.

How big can files be, and how much fits?

Up to 25 MB per file by default; you can raise maxFileMB in config.js to about 50. GitHub likes repositories to stay under roughly 1 GB in total, which is thousands of scanned documents. Compress very large PDFs before uploading.

Can my family use my copy?

Anyone with your password sees everything in your vault, so share it only with someone you'd hand your folder of papers to. For separate vaults, each person makes their own copy with this guide, with their own GitHub account. It takes them 15 minutes too.

Can I change the name or colours?

Yes. The name shown in the browser tab is in index.html (the <title> line) and the colours are at the top of assets/style.css (--kumkum red and --haldi yellow). Edit them on GitHub with the pencil icon like config.js. Keep in mind that edits to files other than config.js can collide with future updates. The code is MIT licensed: keep the LICENSE file and you're free to change anything.

Can I rename my copy later?

Yes, under Settings › General › Repository name. Your app's address changes with it, so update bookmarks and home screen icons. Nothing else needs to change.

How do I stop using it?

Download a backup first (the Backup button in the app gives you one zip). Then delete the token, and delete the vault and your copy under each repository's Settings › General › Danger Zone.

If something goes wrong

Find the message you see. Almost every problem is a setting that didn't stick.

The Actions tab says "Workflows aren't being run on this forked repository"

That's step 2. Click I understand my workflows, go ahead and enable them, then run the workflow as in step 4.

"Browser tests" is green but "Deploy to GitHub Pages" failed

Usually GitHub Pages isn't set to GitHub Actions yet. Do step 3, then open the failed run and click Re-run all jobs (top right).

If the error says Branch "main" is not allowed to deploy to github-pages due to environment protection rules: open Settings › Environments › github-pages, and under Deployment branches and tags add a rule for main (or choose "No restriction"). Then re-run.

"Browser tests" failed

If you only changed config.js, this is almost always a hiccup on GitHub's side: click Re-run all jobs. If it fails again, open the run; the failing check is shown in red at the top. If you changed other files, undo that change and try again.

My address shows "404 There isn't a GitHub Pages site here"

Either the first deploy hasn't finished (wait for the green tick in step 4), or the address is wrong. It's https://YOUR-USERNAME.github.io/a-really-helphul-tool/: your username in small letters, then the exact name of your copy, with the slash at the end.

Setup page: "Token is not valid."

The token was copied incompletely, has expired or was deleted. Make a new one (step 6) and paste it with the copy icon instead of selecting it by hand.

Setup page: "Can't see …. Check the name and that the token has access to this repo."

One of three things: the vault name has a typo (it must match exactly); the username is wrong; or the token's Repository access doesn't include the vault. Open the token on your tokens page, check "Only select repositories" lists your vault, and that Contents is "Read and write".

Setup page: "… is public. The vault must be a private repo"

Open the vault's Settings › General, scroll to the Danger Zone, Change visibility to Private. Then click the setup button again.

Setup page: "Choose a stronger password"

At least 10 characters and not a common word or pattern. The locked key is public, so a weak password could be guessed by a computer trying millions of passwords. A sentence of four or five words is ideal.

The app says "Wrong password" although it's right

Your app is probably still showing the original owner's config. Check that step 8 was committed and that its run in Actions is green, then reload with Ctrl+Shift+R. On a phone where you added the app to the home screen, open it, wait 10 seconds, close it fully and open it again.

It unlocks, but uploading fails

The token can read but not write: set Contents to Read and write on the token (step 6). If the message mentions an empty repository, add a README to the vault (on the vault's page, Add file › Create new file, name it README.md, commit).

"This site is not set up yet"

config.js has no username in it. Do steps 7 and 8.

Something else

Search the project's issues or open a new one. Describe what you did and what you saw, and attach a screenshot, but never post your token, password or config.js.

What is public, what is private

ThingWho can see itWhy that's fine
The app's code (your copy)AnyoneIt's the same open code as the original. No documents in it.
config.js: your username and vault nameAnyoneKnowing the name doesn't let anyone in. The vault is private.
config.js: the locked keyAnyoneLocked with AES-256 and 600,000 rounds of PBKDF2. Useless without your password, as long as the password is strong.
Your documents and clipboardOnly youThey live in the private vault. The app talks only to GitHub, with no trackers or other servers.
Your passwordOnly youNever saved and never sent. It unlocks the key inside your browser.
The original ownerSees nothing of yoursA fork shares code, not data. Your vault and key are yours alone.

For developers

Plain HTML, CSS and JavaScript modules: no framework, no runtime dependencies. To work on it on your own machine (Node 20 or newer, Python 3):

git clone https://github.com/YOUR-USERNAME/a-really-helphul-tool.git
cd a-really-helphul-tool
npm install
npx playwright install chromium
npm run build
python3 -m http.server 8080 --directory _site &
npm test

Every check must print ok; screenshots land in tests/screenshots/. New site files must be added to scripts/build-site.sh. Read docs/AI_HANDOFF.md for the rules of the codebase, and CONTRIBUTING.md if you'd like to send an improvement back.
